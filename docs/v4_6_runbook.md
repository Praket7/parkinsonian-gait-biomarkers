# v4.6 controlled analysis runbook

v4.6 is implemented as a frozen extension of the existing v4.1 through v4.5 analysis chain. It does not require an external cohort, but it does require authorized WearGait source files and two row-level derivatives that are intentionally excluded from Git.

## Required local inputs

1. The authorized WearGait V1 root containing the original clinical CSVs and PKMAS walkway table.
2. `results/v4_3/v1_reconstructed_features.csv`, generated by `scripts/run_v4_3_v1_equivalence.py`. This contains matched PKMAS and independently reconstructed raw-walkway features and is not committed because it is row-level authorized data.
3. `results/v4_4/h4b_session_endpoints_local.csv`, generated by `scripts/run_v4_4_measurement_protocol.py`. This contains the historical four-valid-pass featurewise median endpoints and is not committed because it is row-level authorized data.

Do not replace either local table with hand-entered numbers. If either is missing, regenerate it from the authorized source using the historical versioned pipeline.

## Freeze check

Before any real v4.6 result is produced, run

```bash
python scripts/check_v4_6_freeze.py
```

The checker verifies the v4.6 preregistration/config and raw-byte hashes for the frozen v4.1 model plus the historical v4.3 and v4.5 artifacts.

## One-command execution

```bash
python scripts/run_v4_6_all.py --v1-root /path/to/authorized/WearGait/V1
```

This executes, in order

1. final-score analytical agreement
2. six-plus-month deviation-pattern conservation
3. healthy-reference uncertainty propagation
4. aggregate-only report generation
5. unsupported-claim audit

The same analyses can be run separately with

```bash
python scripts/run_v4_6_score_agreement.py --v1-root /path/to/V1
python scripts/run_v4_6_deviation_geometry.py
python scripts/run_v4_6_reference_uncertainty.py --v1-root /path/to/V1
python scripts/build_v4_6_report.py
python scripts/check_v4_6_claims.py
```

## Output policy

Aggregate scientific outputs are written under `results/v4_6/`. Participant-level tables use filenames ending in `_local.csv` and are intended to remain local. The repository's `results/*` ignore rule prevents normal Git staging of generated v4.6 results unless a result is deliberately reviewed and released.

Do not publish row-level participant identifiers or source clinical data.

## Interpretation

The final-score agreement analysis tests analytical propagation through the nonlinear frozen score. It does not establish clinical validity.

The deviation-direction analysis tests whether the multivariate pattern of departure from the healthy reference is conserved within a person across visits separated by at least six months more than under random cross-person pairing. It is not short-term test-retest reliability.

The healthy-reference bootstrap measures sensitivity to which healthy participants define the reference. Its percentiles are reference-estimation uncertainty, not participant-sampling confidence intervals.

Regardless of outcome, v4.6 does not establish diagnosis, treatment response, progression tracking, clinically meaningful change, short-term state-controlled repeatability, independent full-score transport, or general multi-site validation.
